# Owned actual private player fixture

This is staged code. No player, Eww daemon, D-Bus session or GUI was started by its author. The pure fixture tests use temporary files and mocked MPRIS/IPC. Current source native acceptance remains pending. The coordinator ran earlier source revisions; those receipts are historical for the current pause/client-flag revision.

The source pins a real copy of the installed `mpv-mpris` 0.7.1 plugin and its package copyright. Plugin SHA256 is `4a9622b06dbc784e91a1c5f911c4e503980732ea2d633683b8bca4eb430e9fab`. Installed mpv 0.37.0 documentation explicitly supports C plugins loaded through `--script`.

The coordinator must run this inside its existing private HOME, display and D-Bus session. `CURRENT_COLLECTION_HOST_DISPLAY` and `CURRENT_COLLECTION_HOST_BUS` must still identify the host values. `DTS_PRIVATE_ROOT` must be a fresh owned directory below `/tmp`. The guard derives the receiver HOME/display from the owned private bus peer process. It normalizes X server numbers and Unix bus endpoints, refusing host aliases and arbitrary HOME paths. mpv receives a separate owner-only temporary player/home and explicit config/data/cache/state/runtime directories through a small environment allowlist. Eww clients validate that saved binding from the attested receiver HOME. IPC requires an owned Unix socket plus SO_PEERCRED for the exact mpv PID and birth identity.

Use the manifest-bound version2 copies for runtime evidence:

1. Invoke `/usr/bin/python3 -B <bundle-version2>/private/launch.py prepare` with the owned environment. This copies the unchanged frontend plus the version2 private backend/player library.
2. Invoke `/usr/bin/python3 -B <bundle-version2>/private/player/launch.py start` with the same environment. It copies the pinned plugin into the temporary player directory, generates two owned 30-second PCM WAV files, and launches `/usr/bin/mpv` with no config, no automatic scripts, the explicit owned plugin, null audio/video, no window and the owned IPC socket. mpv output goes to `player/mpv.log`, never a captured daemon pipe.
3. Start/open Eww through the version2 private launcher. Its `scripts/backend.py action media ...` strings are unchanged. Only the private backend implementation routes media to the discovered exact MPRIS name and unique owner bound to the owned mpv PID and birth identity. Other controls retain their owned mock behavior.
4. Invoke `/usr/bin/python3 -B <bundle-version2>/private/player/launch.py verify` to exercise pause, play, seek35%, next and previous through that MPRIS endpoint. Each action verifies actual mpv IPC state. After the original five receipts, verify pauses through the same exact owned MPRIS endpoint and requires matching IPC/PlaybackStatus readback; acceptance adds final_state:paused and a separate capture_stability receipt. Physical frontend click/key receipts remain a separate coordinator test.

Copy `player/{prepared,discovery,acceptance,cleanup}.json`, `player/transport-actions.jsonl` and relevant logs to evidence before deleting the private root. Record the coordinator's overall private-process cleanup receipt too.

Additional commands are `status` and `action <toggle|play|pause|seek|next|previous> [argument]`. Seek accepts a finite percent 0..100; 100 clips just before the track end to avoid crossing the owned playlist during readback.

Coordinator containment detail: mpv uses a different temporary HOME from the receiver. The generic receiver-HOME reaper alone does not cover that child. Keep the exact owned PID/birth binding (prefer a coordinator-held pidfd), stop it in a nested finally, record cleanup, and include that child in outer timeout cleanup before deleting the private root.

The standalone coordinator utility is `private-player/cleanup.py`; it is deliberately outside the authored bundle. Import it with the coordinator's no-bytecode Python runtime and call `cleanup.cleanup(run_directory, saved_host_display)`. It reads only the owned regular `run_directory/owned-private-player-root.json`. The exact schema and eight environment keys are recorded in `handoff.json`. Register that receipt before starting the player with null PID/birth; after successful startup copy PID and the numeric-string birth from `player/binding.json`. Preserve the receipt in the run directory even if the temporary root is deleted.

Outer cleanup uses the saved environment and exact executable/argv/UID/PID birth without contacting the bus. For an unbound receipt, exact private script/socket/track argv identifies a candidate before environment and birth reads. Unrelated processes are excluded. Identified private-root evidence that is unreadable, or any bound identity mismatch, refuses cleanup. Signals use a pidfd acquired and rechecked for the same birth, with bounded TERM and KILL waits on that same fd. The utility returns structured cleanup evidence; the coordinator writes success or failure evidence. Quiesce all start-command supervisors and launchers before scanning, so no new child can appear after cleanup.
