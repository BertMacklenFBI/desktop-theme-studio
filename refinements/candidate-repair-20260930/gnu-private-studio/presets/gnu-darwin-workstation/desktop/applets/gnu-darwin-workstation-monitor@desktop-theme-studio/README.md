# GNU-Darwin Workstation monitor

Newly authored WMMon/WMNet-style adaptation, not recovered historical widget code. Four64px tiles show CPU/MEM/RX/TX from local /proc reads; no subprocesses, network requests, daemons or settings mutation. `metrics.js` is pure GJS; `applet.js` owns one GLib1Hz timer created only when added and removed on disposal. CPU sums first eight counters, omitting guest columns already represented in user/nice. Memory uses MemTotal−MemAvailable. Route selection prefers the lowest-metric usable IPv4 default, with IPv6 fallback. Reset, missing and stale data show -- rather than invented zero. Numeric throughput remains real while RX/TX graphs share a rolling54-sample ceiling. Colors derive from canonical palette/ANSI in style.js.

Run `gjs test_metrics.js` with this directory as working directory.61 assertions cover guest-heavy CPU accounting, available memory, route filtering/ties/IPv6, warmup/zero/reset/missing/stale samples, bounded histories, rate formatting with explicit K/s/M/s/G/s and six-character boundary cases, copied snapshots, actual applet lifecycle via in-process stubs, and real Cairo drawing APIs on a memory-only surface. No display or real timer is created by fixtures.

`getMetricsSnapshot()` returns copied scalar data and timer/disposal state. The coordinator verifies advancing real samples and retained-object disposal in a private Cinnamon session. metadata allows numbered instances for transactional settings restoration; canonical controller installs exactly one. interval-seconds is schema-locked to1, matching implementation. Original personal music, commands and other presets are untouched.
